# A 机地面联调与双机协同优化（2026-10-16）

本轮按用户选择优先验证 A 机地面联调；所有改动在 Ubuntu 22.04。未 SSH、未更新已部署 A 机版本、未输出真实 PWM。

## 行为变化

- A、B 与 release_guard 对取消投放锁存。操作员恢复飞行不重新开锁；必须落地检查机构、载荷和持久化尝试记录，再按操作流程重新启动任务。不可在空中重启任务清除锁存，不可自动删除尝试记录。
- guard 接受首个有效计划后不允许其他时间覆盖；错过执行窗口、执行时权限不满足也终止该轮。授权与开锁等待期间都检查双机 permits/actions。
- B 校验 release_cmd 长度、有限值、动作值、A 源时间新鲜度、单调顺序和计划一致性。延迟消息不会因刚收到而变新鲜；确认真实脱离后，旧 ACK/取消消息不覆盖脱离时间。
- A 校验 B 就绪数据的非负误差/不确定度和布尔标志；新鲜度按源时间计。异常时钟探测消息不会导致索引异常。
- B 保留传感器脱离时刻，另设当前轨迹起点。使用新鲜的释放后载荷位置/速度和 B 速度计算剩余接取时间、碰撞相对速度及刹停高度；样本年龄最多 0.15 秒，按重力短时传播到当前。不可行则 HOLD/MISS。
- 保持直出 1700µs，计划脱离 T、T−1.5 秒授权；实测近似 1.5 秒仍不是完成抖动验收的标定。真实 enabled/calibrated 仍 false，真实传感器门禁保留。

## A 机模拟联调入口

在 Ubuntu 22.04 工程目录执行：

```bash
sudo -n python3 tools/run_a_ground_isolated.py
```

该入口用 root 创建独立网络命名空间并打开其中 loopback，ROS 和测试以工程所有者普通用户运行；退出即销毁命名空间。结果写入本目录，不改系统服务、Jetson、引脚或飞控。只运行模拟 PWM。

check_a_ground_ros.py 在测试进程中取消 A 的飞行定时器并替换任务许可为测试夹具，模拟 B 就绪和安全监督，仅运行真实协商函数、guard 和 mock servo。它不是实机启动入口，也不能证明飞控自检或物理机构已验收。Mock ready/event 不发布到真实硬件就绪/释放话题。
