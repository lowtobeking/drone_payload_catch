# 当前安全实现与操作

2026-10-13。用户已授权本轮修改，普通强制停止采用“取消交接并保持”；降落、飞行终止分别提供入口。本文件覆盖历史文档中“待决定”“未实现”的说明。

## 起飞门禁

- 双机位置、速度、姿态、状态、自检标志、估计器、failsafe、电池必须完整且新鲜，源时间戳必须推进，非有限值拒飞。室外另查 GPS；真机必须有独立 RC 信号。
- 每台电池 connected=true、warning=0，剩余电量至少 40%。没有降低门限或跳过自检的启动参数。
- 两台飞控完整参数读取和安全策略检查通过，产生 60 秒检查记录；节点还要连续 3 秒核验双机健康，并持有新鲜监督许可，才发送 ARM／Offboard／任务设定点。
- 真机检查 RC 输入启用、独立紧急开关和模式接管映射；只读参数，不自动改写飞控。软件不能禁止绕过工程的人工 RC 解锁。
- 真机 M6 起飞前还须收到真实相对定位、真实载荷状态、机构就绪。机构驱动应持续发布 `/payload/hardware_ready`，不能用固定 true 代替实际自检。

## 飞行中的处理

`safety_supervisor` 独立于 A/B 任务进程，每 50ms 检查双机健康与任务心跳。任务停止、源数据断流、失效或安全状态异常时撤销双机交接许可、取消待释放、锁存停止。导航健康时请求 PX4 AUTO_LOITER；导航失效时不继续发送盲目的位置／速度指令，交还 PX4 失效保护和 RC。

持续故障 3 秒升级为降落请求，计时在任务先暂停后仍独立运行。请求 A 降落时保守安排 B 先降落，只有 B 的新鲜落地检测和新鲜上锁状态都确认后，才请求 A 降落；不比较两架飞控独立本地原点的坐标。B 状态未知时 A 不获降落许可。若导航失效、整机通信中断或 PX4 自身失效保护先接管，软件无法保证保持或双机分离，必须由飞控／RC 和经验证的场地处置方案承担。

HOLD 清除任务速度和加速度前馈；PULLBACK 从零任务速度生成围栏安全速度并清除任务加速度。位置发布接口也服从安全状态。任务退出 Offboard／人工接管后不重发任务指令，也不以恢复通信自动恢复交接。监督节点确认模式后若模式再次改变，停止 hold／land 重试，尊重人工／飞控接管。

## 释放与捕获

`release_guard` 是最后释放联锁。原 `/payload/release_at` 只表示计划；执行必须同时满足：权威任务许可不超过 0.2 秒、监督状态不超过 0.5 秒、双机健康且已解锁并处于 Offboard、两任务源可用、安全状态允许、到点不迟于 0.10 秒。取消后旧计划不能重放，监督重启清除计划，执行一次后不能再次释放。

模拟载荷已改为只消费 `/payload/authorized_release`。实际硬件驱动尚未存在于工程中，必须接入这个接口，校验 `stamp`、一次性 `nonce`，同时处理取消与许可超时；不能继续订阅原计划直接开舵机。实际分离后应由物理传感器发布 `/payload/released`。在硬件驱动及失电行为验收前，这里完成的是软件联锁，不能声称实际机构已安全。

释放前检查捕获高度和制动计划是否 feasible；飞行中计划不可行立即停止追击。B 等待实际分离确认，真机还等真实载荷开始下落，不能只因计划到点就下潜。真机捕获须同时有新鲜几何窗口、接触事件、载荷存在，并保持至少 0.10 秒且有推进的观测；取消了 near 超时假报捕获。接空并不阻止已释放载荷落地，需实物接网或隔离区。

## 相对定位的数据合同

- RTK `NavSatFix` 保留真实采集时间，协方差已知、有限、正定／半正定、对称；A/B 合成标准差不超过 0.03m，源时间相差不超过 0.10 秒，数据年龄不超过 0.5 秒。
- 数组合同为 `[source_stamp, x/lat, y/lon, z/alt, sigma_m]`；旧无时间戳数组拒绝。时间必须与 ROS 时钟一致，不能把缓存收到时间当采集时间。
- 载荷 `/payload/state` 和 `/drone_a/state` 为 `[source_stamp,x,y,z,vx,vy,vz]`；缓存不重贴当前时间。重复／乱序不刷新新鲜度。
- RTK 模式订阅 B PX4 位置和 A/B 姿态；杆臂定义统一为“天线到 PX4 机体定位原点”的机体 FRD 向量，补偿之后发布 A 机体位置到 B 世界系。释放偏置和漏斗安装高度由任务另计，避免重复。
- 原示例天线到托盘／释放点的杆臂已失效；`run_m6_real.sh` 要求填写实测 A_LEVER/B_LEVER。直接 launch 的零值只适用于物理共点，不能当作标定。世界偏移、PX4 z bias、传感器时钟和最坏延迟须实测。

## 操作员入口

在已启动且 ROS 环境已 source 的终端使用以下命令。下面只是操作说明，本轮验证没有执行这些控制命令。

```bash
# 双机暂停、取消交接；链路恢复也不自动继续
ros2 topic pub --once /safety/pause std_msgs/msg/Bool '{data: true}'
# 重新授权：只允许释放前、双机健康／源可用；重新对齐，不续跑旧轨迹
ros2 topic pub --once /safety/resume std_msgs/msg/Bool '{data: true}'
# 结束任务并降落：B 先落地确认，再请求 A
ros2 topic pub --once /safety/land std_msgs/msg/Bool '{data: true}'
# 紧急飞行终止：可能立刻坠落，与普通暂停不同
ros2 topic pub --once /safety/kill std_msgs/msg/Bool '{data: true}'
# 查看 actions / permits / progress / reasons
ros2 topic echo /safety/state
```

每个动作支持 `_a`／`_b` 后缀。停止任一架会取消双机释放；恢复作为双机操作处理。已释放、正在降落、终止、人工接管后不能恢复任务，须结束并重新自检。Ctrl+C 不作为安全停止按钮。

命令以 system 255／component 191 发出，匹配目标飞控返回的 ACK；最多 8 次、间隔 0.3 秒。状态区分 PENDING、ACK_REJECTED、EXECUTION_UNCONFIRMED、MODE_CONFIRMED、LANDED_CONFIRMED。ACK 接受且观察到相应模式才确认模式；land 还要落地和上锁才确认完成。termination 模式确认不能证明电机真实 RPM 已归零，须拆桨台架／电调遥测验证。

独立节点不能覆盖整台伴随计算机断电或 ROS/DDS 故障；两机必须保有经验证的独立 RC 模式接管／紧急开关和 PX4 Offboard/RC 失联策略。

## 验证范围

新增 `tools/test_safety_runtime.py` 在离线执行实际节点方法，覆盖最终发布消息、陈旧／重复／非法数据、暂停锁存、显式恢复、挂死任务、持续故障、人工接管、ACK 拒绝／重试、顺序降落、释放取消／超时／单次、物理捕获、RTK 质量与坐标。

本轮仅离线测试、接口导入／配置和 ROS 构建；没有起飞、解锁、发送真实控制命令，也没有重新取得历史 SITL 成绩。0.5 秒新鲜度、3 秒升级、0.03m RTK 等为当前软件假设，需按真实发布频率、最坏延迟、停止距离和制动能力完成拆桨台架→HIL→受控场地验收。未实现废墟障碍物建图／避障／安全着陆区识别；不能把受控试验的保持／降落策略视作任意废墟中的安全保证。
