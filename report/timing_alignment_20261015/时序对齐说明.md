# 直接1700µs投放的时序对齐

用户在取消缓变后重新测量，确认应用1700µs至物体实际脱离仍约1.5秒。工程已用这次观测覆盖旧的“直出尚未测量”状态；参数为release_delay_s=1.5、delay_reference=operator_direct。

以计划脱离T=12:00:10.000为例：

| 时刻 | 行为 |
|---|---|
| 12:00:08.300 | 双方协商通过，A通知B计划脱离T |
| 12:00:08.500 | guard再次核对许可后授权，A直接请求1700µs |
| 08.500到10.000 | 载荷仍按挂载状态处理，B持续对正；没有倒计时虚构released |
| 约12:00:10.000 | 真实反馈给出detached_at；A清场，舵机停止，B按新鲜载荷观测接取 |

迟到命令在worker写入前被拒绝，写入开始/结束时间回执供驱动检查执行窗口。它们只表明软件对sysfs的操作时间范围，不是引脚第一脉冲实测。真实传感器边沿由release_event带到B，扣除时钟偏差后保留原时刻，不把消息收到的时间当成物体刚脱离。重复/错会话/过期/模拟/不同代码配置事件被拒绝。实际下潜仍需新鲜下落观测，其物理控制效果没有经过HIL或实飞验收。

一次“约1.5秒”尚不能证明±20ms重复精度；不将近似值升级为完整飞行标定。enabled=false和calibrated=false、真实反馈与全部起飞门禁保留。当前已完成源代码时序对齐，未部署到Jetson，未输出真实PWM。正式启用需同步两机时钟并以最终执行链重复测量延迟分布、反馈及接取控制效果。
