# M6-moving 加快：编队同速速度边界与控制优化

> 问题："能加快速度接好吗？需要优化控制算法吗？"

> **决策（定稿）**：M6-moving 的**支持速度 = 0.5 / 1.0 m/s**（各 2/2 完美执行）；
> **2.0 m/s 保留记录、不再优化**。

## 1. 结论

- **支持速度 0.5 / 1.0 m/s 已完美执行**（见 §4b）。
- **需要优化控制——而且已经做了**：原编队控制用**延迟/带噪的 A 速度估计**做前馈，**2.0 m/s 就发散**；
  改成 **"已知 `formation_vel` 死推算参考 + 相对测量小幅校正"** 后，2.0 m/s 稳定捕获。
- **2.0 m/s 暂保留**：仍不稳（释放门限 / DIVE 横向 lead 边际），**不再优化**；
  **3.0 m/s** 亦不追求。

## 2. 控制优化（关键）

**问题（旧）**：`FORMATION` 相位 `v = a_vel_est + kp·(a_est − pos)`——
`a_vel_est` 是**相对定位（延迟+噪声+EMA）估出来的**。高速下它与真实值有偏差 → **正反馈发散**：
实测 @2.0 m/s：B 速度冲到 3.28、x 飞到 80m、掉高到 z=+0.9（失控）。

**改法（新）**：
```
进入 FORMATION 记录 B 自身起点 (p0,t0) 与初始相对偏移 rel0
参考 ref = p0 + formation_vel·(t−t0)              ← 死推算（用【已知】formation_vel）
v = formation_vel + kp·(ref − pos) + kp_rel·((a_est − pos) − rel0)
     ↑ 已知前馈            ↑ 参考跟踪            ↑ 相对测量只做小幅校正
```
**不再估计 A 的速度**；相对测量只用于慢修正。

**结果**：@2.0 m/s → `B vel≈2.0 稳、relA≈1.7 稳` → `FORMATION aligned rel_xy=0.073 rel_vxy=0.158 → release` → **`STACK CAPTURED horiz=0.085m`**，无 failsafe。

## 4c. 及时释放 + 超时保护（已实现 ✅）

**问题**：释放门限要求对齐持续保持 `align_hold_s`，而相对定位有噪声会不断重置 → 释放**磨蹭十几秒**（两机白飞几十米）；
若一直对不齐，B **永远不释放**（无超时）。

**改法**：
1. **容忍短暂抖动**（`align_reset_tol`，默认 0.25s）：只有**连续失配超过它**才重置 hold；
   门限本身用低噪量（`rel_vxy` 对已知 `formation_vel`）→ **及时释放**。
2. **释放超时保护**（`formation_timeout_s`，默认 12s）：超时未释放 → **中止投放**：
   B 发 `/formation/abort` + 安全悬停→降落；A 收 abort → 停止巡航、**保留载荷**并降落（不投）。

**SITL 验证**：
```
# 及时释放：编队 ~3.5s 即捕获（之前 10–20s）
B: ALIGNED → /formation/start
*** STACK CAPTURED *** horiz=0.163m   → 双机落地

# 强制超时（formation_timeout_s:=1.5）
B: 编队释放超时 (2s) → 中止投放，安全悬停→降落
A: 收到 /formation/abort → 停止巡航，保留载荷并降落
（无 STACK CAPTURED；双机 Disarmed by landing；无 failsafe）
```

## 5. 要再快（下一步）
1. **DIVE 横向 lead 加强**：用载荷速度外推到接触时刻（已有 ZEM 雏形，可调 `zem_gain`/提高 lead）。
2. **编队相对校正增益自适应**（`form_kp_rel` 随速度/延迟调）。
3. **释放闸自适应**（按速度放宽 `align_vel_tol`，或用"预测落点余量"判定）。
4. **大漏斗/更深漏斗**提高口径余量。
