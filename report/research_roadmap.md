# 研究路线图 · 面向"双机协同空中载荷交接"（协调方向）

> 目标：把现有 `drone_payload_catch` 从"工程集成 + 仿真验证"提升为**可发表的研究工作**，
> 研究焦点定为 **UAV 协调（coordination）**：两台无人机在**不确定性、通信受限、时序离散事件**
> 下协同完成"空投—空中捕获"。
>
> 本文给出：研究地图 → 建议核心贡献 → 与现状对比 → 需补的理论 → 实验方案 → 与代码映射 → 里程碑。
> 面向对象：本项目的作者 / 接手的研究者。

---

## 0. 一句话定位

> **研究问题**：在两机相对状态**不确定**、通信存在**延迟/丢包/时钟偏差**、交接是**离散事件**的条件下，
> 如何**协同决策**（释放时机、双方机动、信息共享）以**最大化捕获概率并保证安全**？
>
> **一句话贡献**：给出**不确定性感知、通信鲁棒的协同交接协议**，并提供**捕获概率下界 / 安全证书**，
> 通过系统消融（state vs intent、direct vs authority、含/不含不确定性）量化协调收益。

**为什么是协调**：现有负结果 `report/coordination.md` 已证明——A 的**小幅位置偏移与释放时刻 `t_r` 冗余（δ\*=0）**，
所以协调的增益**不在"A 也动一点"，而在信息协议与时机决策**。这正好把研究焦点锁定在
**"谁在何时、基于什么信息、以什么保证做释放决策"**。

## 1. 研究地图：现状 vs SOTA vs 缺口

| 维度 | 本工程现状 | 相关研究（方向） | 缺口 / 机会 |
|---|---|---|---|
| **问题形式化** | 任务清晰，代价函数启发式 | 交会/对接（空间交会、aerial refueling）、随机最优停止 | 无**形式化**（概率/保证） |

| **多机/扩展** | 单对单、单载荷 | 多机任务分配、多载荷调度 | 交接时序调度（长期扩展） |
| **实验** | 纯 SITL、N=5/档 | 真机 / HIL / 高保真 | **真机两机**（审稿门槛） |

## 2. 建议的核心研究贡献（C1–C5）

### C1. 不确定性感知的"释放权威"（Uncertainty-aware release authority）★核心
把释放决策形式化为：给定相对状态估计不确定性 σ、通信延迟 d、剩余时间 τ，
选择释放时刻 `t_r` 最大化 `P(capture)`：

```
capture ⇔  ‖p_B(t_c) − p_p(t_c)‖ ≤ r_eff  ∧  ‖v_B − v_p‖ ≤ v_c
目标:  t_r* = argmax_{t_r}  P( capture | x̂_A, x̂_B, σ, d )
保证:  存在证书  pred_miss(t_r) + k(ε)·σ(d) ≤ r_eff − margin   ⇒  P(capture) ≥ 1−ε
```

- 现状：`a_node` 的余量闸 `pred_miss = rel_xy + |drift| + k·σ ≤ eff_r − margin` 是**启发式**，σ=常数/在线残差。
- 论文：给出 **`P(capture)` 下界**与 `k(ε)` 的推导（把 σ 与 delay 映射到脱靶分布），并证明在何种条件下该释放策略最优。
- 已有素材：`_b_sigma` 上传、`eph/epv`（round4）、`release_sigma_max`。

### C2. 通信鲁棒的交接协议（Communication-robust handover protocol）
- 现状：`handshake_timeout`、`commit_hold_s`、`release_lead`、`ready_timeout` 都是**经验常数**。
- 论文：建模延迟/丢包/时钟偏差对释放时序的影响，提出**延迟补偿的释放调度**并给**时序误差上界**；
  对比 `direct`（B 单边用延迟估计）vs `authority`（A 用精确状态 + B 质量上报）。
- 可复用：`/coord/ping|pong` 时钟同步、`/drone_b/ready`(含 σ)、`/drone_a/release_cmd`、`/payload/release_abort`。

### C3. 信息共享的价值：state vs intent（信息充分性）
- 现状：同时有 state 广播与 intent（预测落点），但**未系统对比**。
- 论文：形式化"共享**计划（intent）**是否比共享**状态**更省通信/更鲁棒"，并实验量化
  —— 在给定延迟/丢包下，intent 能把对正误差/释放余量改善多少。
- 可复用：`a_node._coord_tick` 的 intent 广播 + `b_node` 的 `use_intent` 开关。

### C4. 协同机动：A 速度/高度 × B 的联合规划
- 现状：A 恒速/编队，B 单独对正；负结果证明"小幅位置偏移"无益，但 **A 调整速度/高度**有效
  （见 `report/drag_rejection.md` 迎风预补偿、`geom_opt.py`）。
- 论文：把双方可调量（A 的速度/高度、B 的待命 gap/下潜）联合优化，目标最小化 B 的 Δv / 峰值 a
  或最大化捕获余量；给出分布式求解（A、B 各自局部信息）。
- 可复用：`rendezvous.solve_cooperative`（已有雏形，δ 维度可换成 A 速度/高度维度）。

### C5. 交接事件感知的分布式安全证书
- 现状：分级安全状态机（round2/3）+ σ keep-out + 姿态滤波（round4/5），但**无形式化保证**。
- 论文：设计**handover-CBF**：在"接近→对正→释放→下潜"过程中保证
  ①两机不碰撞（keep-out 不变集）②捕获锥在释放后保持可达；去中心化实现（各自只知局部 + 通信）。
- 可复用：`px4_iface._safety_update`、`_fence_velocity`、`_attitude_govern`、`_gap_eff`。

## 4. 需要新增的理论工具

1. **随机可达性 / 捕获锥**：给定 σ，B 在 τ 内可达集合与捕获锥的交集（概率版）。
2. **随机最优停止**：释放时刻作为停止时间，最小化期望脱靶/最大化 P(capture)。
3. **控制障碍函数（CBF）/ 控制不变集**：两机 keep-out 与捕获条件的不变性。
4. **网络化控制时序分析**：延迟/丢包下的事件触发释放（event-triggered）与其时序误差界。
5. **信息论/充分统计量视角**：state vs intent 的比较（"计划"是否是对决策的充分统计量）。

## 5. 实验方案（分阶段）

### 阶段 0：固化基准（1–2 周，几乎零新代码）
- 把现有协调能力做成**标准 benchmark 配置**：`direct/authority × state/intent × σ∈{0,0.05,0.1} × delay∈{0,0.1,0.2}`。
- 指标：捕获成功率、捕获时水平偏差、相对速度、最小 A-B 间距、释放时刻的余量、通信量。
- **已实现**：`tools/bench_coord.py`（网格 + Wilson 置信区间 → `report/coordination_benchmark.md`）。
- 命令：`python3 tools/bench_coord.py --quick` / `--full --reps 3`；也可 `COORD=handshake use_intent:=... `。

### 阶段 1：C1 概率释放保证（2–4 周）
- 离线（`tools/offline_run.py`、`tools/stack_run.py`）推导并验证 `P(capture)≥1−ε` 证书；
- SITL 扫描 σ×delay，比较 **启发式闸** vs **证书闸**（触发即弃投/重试）。
- 产出：`P(capture)`—σ—delay 曲线；证书的保守度/覆盖率。

### 阶段 2：C2 + C3 信息与通信（3–5 周）
- 消融：`direct` vs `authority`；`state-only` vs `+intent`；
- 延迟 0/0.1/0.2/0.4s、丢包 0/10/30%、时钟偏置 0/5/20ms；
- 产出：**协调收益 vs 通信条件**的定量结论（预期：authority+intent 对延迟最鲁棒）。

### 阶段 3：C4 联合机动（3–4 周）
- 扩展 `solve_cooperative`：决策变量 = {A 速度/高度, t_r, B gap/下潜}；
- 目标：最小化 B 峰值 a / 最大化余量；分布式求解。
- 产出：相比"B 单边对正"的余量/能耗改善；与"δ 位置偏移"负结果对照。

### 阶段 4：C5 安全证书（4–6 周）
- 设计 handover-CBF，接入 `px4_iface`；
- 验证：注入扰动/估计跳变时**安全不变性**（不碰撞 + 捕获条件）与可达性。

### 阶段 5：真机/扩展（长期）
- 两机真机 + UWB/视觉；或 HIL。多机/多载荷调度（延伸）。

## 7. 风险、最小可发表单元（MPU）

- **最大风险**：审稿门槛要求**真机**。若资源不足，需用 **理论 + 高保真仿真 + 少量真机/HIL** 组合降门槛。
- **最小可发表单元（MPU）**：
  - **C1（概率释放保证）+ C2/C3（通信与信息消融）+ C5（安全证书）** 三件套，
    以 SITL 为主 + 1–2 组真机验证。
  - 叙事线：**"协调的价值在信息与时机，不在位置微调"**（用 δ\*=0 负结果开头）→
    提出不确定性感知、通信鲁棒的协议与证书 → 系统消融证明。
- **最坏情况兜底**：若真机不可行，可发**基准/负结果**类工作（阶段 0–3 + 严谨统计）。
