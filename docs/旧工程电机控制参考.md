## 实际控制链

旧工程 `Multi-UAV-simulation-full/mpc_control/mpc_node.py` 使用 PX4 Offboard / TrajectorySetpoint。`publish_offboard_mode()`（约2461行）启用 velocity；`publish_position_setpoint()`（约2480行）填入位置与速度前馈，`publish_velocity_setpoint()`（约2495行）填入速度。实际字段如何参与控制仍取决于 Offboard 模式及现场 PX4 固件，不能仅凭函数名称推断闭环效果。

在这条任务控制链中，Jetson 不直接指定单个电机 RPM。PX4 根据定位、姿态及任务设定点计算推力/力矩，经控制分配和电调驱动电机。飞机速度（m/s）、归一化推力/油门、电机实测转速（RPM）是不同量；没有相应电调转速遥测时不能声称已验证 RPM。

当前工程 `payload_catch/px4_iface.py` 的 `broadcast_offboard_mode()` / `publish_velocity()` 也使用 Offboard velocity / TrajectorySetpoint，并保留监督权限、健康检查、设定点限制和操作员停止逻辑。因此无需为了参考旧工程，另加绕过 PX4 的电机直控路径。

### 针对双机投放/接取的建议

1. **先保持已有稳定的机体控制参数。** 姿态/角速度增益、电调协议、输出映射、THR_MDL_FAC和悬停推力初值，先与当前飞控及本机历史身份核对。无桨运行不能重新标定带载悬停或推力储备。不能仅凭某份快照将0.50改成0.30，或为了限速直接降低MPC_THR_MAX。
2. **首轮完整飞行宜选静止投放。** A/B稳定悬停并完成对正后再释放，后续再考虑移动交接。作为待验证的任务层候选，转场水平速度可先取0.5m/s、近距离对正取0.2m/s；起飞0.5、普通降落0.3m/s可参考旧配置脚本。上述数值没有写入配置，不是已验收安全边界，也不能直接用作B的接取下降速度上限。
3. **B的动力约束优先于慢速偏好。** 当前真机launch默认a_dive=3、a_brake=6m/s²，auto_min_dive=true可能算出零下潜，但自适应/其他场景仍需核实。a_brake=6用于预测刹停距离，而旧快照MPC_ACC_UP_MAX只有约1.95或4；这提示规划可能过于乐观，不能认定能实现6。PX4各加速度参数对外部速度设定点的具体作用需结合实际固件确认，不能简单把它们当作已测物理能力。应使用B接物增重后可持续实现的保守能力、速度限制、响应延迟与离地净空重新评估接取可行性；不能靠修改参数名字宣称匹配。
4. **A/B分别验证载荷突变。** A空载/带载及B空载/接住后至少四种工况。A减重可能短暂上冲；B增重及接触冲量会增加高度损失。默认由PX4闭环控制，不在1700µs开锁命令发出时人为跳变飞行推力：此时物体约1.5秒后才可能脱离，且没有锁扣反馈，过早改变推力可能破坏悬停。
5. **1.5秒是机构动作提前量。** 开锁等待阶段持续检查双机位置、速度、通信和释放许可。自由下落时间另由实际载荷释放点到托盘口的距离计算，不能让B等动作完成消息后才开始准备。计时估计不等于实测脱离，B实际接取仍以新鲜物块观测为依据。零初速、1m有效落差的理想落时约0.45秒，说明通信/观测/速度环延迟会占用明显的接取窗口；真实落差须扣除机构与托盘偏移。
6. **垂直堆叠有额外气动和几何约束。** B位于A下方会受到下洗气流影响；物体通道不能穿过B桨盘。气流扰动、桨盘净空、定位不确定度和舵机释放抖动都需纳入释放条件。没有这些实测依据时，旧工程的普通悬停成功不能作为本任务安全证明。
7. **电池检查继续处理来源问题。** 历史快照记录4S，但当前遥测曾出现约16.44V却cell_count=1。需查明源消息与实际配置，不能只把串数字段改成4后视为排查完成，也不能据此直接认可剩余电量百分比。

建议落实顺序：只读导出当前飞控参数并匹配本机历史身份 → 比较配置差异 → 确认A/B空载与带载动力/响应边界 → 在这些约束下重新验证任务规划 → 按阶段地面/HIL及受控飞行验收。当前室内无桨阶段可继续完成前两项和软件拒绝测试，不产生带载飞行动力结论。
