# 无锁扣传感器的定时开锁模式

用户于2026-10-16明确：锁扣/物块没有真实反馈传感器，要求执行开锁动作后结束。此说明覆盖此前“真实释放必须有锁扣传感器”的要求；其他起飞与双机安全门禁保留。

## 行为

正式配置显式选择confirmation_mode: timed。有效授权仍由release_guard产生，核对双机安全许可、会话、owner、一次性nonce、源时间和计划时刻；动作前先持久化单次尝试记录。到T-1.5秒直接写1700µs，无1500µs缓变，实际写入必须带时间回执并满足原调度窗口。

动作时长从实际写入时间范围末端换算到单调时钟计算约1.5秒，不从SSH回包或事件接收时刻重新等待。期间持续核对安全许可与PWM worker健康。完成时先关闭输出/恢复引脚；关闭失败进入FAULT，不发送成功事件。正常关闭后进入ACTION_COMPLETE，发送release_action_complete及带confirmation_mode=timed的release_event。估计脱离时间是实际写入完成时刻+1.5秒；实际动作结束时刻另外记录。

不订阅伪造反馈来满足门禁；timed模式不要求锁扣反馈，也不推断物块在位、锁住或实际脱离。physically_confirmed/physical_released为false，detached_at为空，不发布物理/payload/released Bool。日志明确记录动作完成、物理脱离未确认。传感器sensor模式保留原逻辑，不能混用两类事件。

## A/B衔接

A核对本轮计划、会话、模式、版本/配置指纹和事件时间，接受定时动作完成后按任务进入清场，状态报告release_unconfirmed=true。A不接受Bool冒充定时完成。

B按相同标定配置指纹选择证据类型；timed事件只写estimated_release_at，不填measured_release_at，拒绝错模式、旧事件、重复事件和模拟事件。硬件状态的新鲜度来自驱动状态与安全心跳，不伪造feedback_stamp。B接取前所需真实物块位置/下落观测、相对定位和实际捕获判据保留；此变更只取消A锁扣/脱离传感器要求，不把B的视觉/物块观测数据补成假值。没有新鲜下落观测时不能盲目下潜。

## 故障与重试

开锁前或过程中操作员停止、任一机许可撤销、监督信号丢失、worker失败、调度超时均锁存故障并停止输出；没有完成事件，不自动重试或反向重新锁扣。独立worker的0.25秒父心跳和2秒最长输出保留。已持久化的动作记录跨进程重启继续阻止重复开锁，重新装载后须地面复位，不能自动删除尝试记录。

没有传感器就无法自动确认卡扣是否真的打开、物块是否卡住或是否提前脱落。1.5秒来自操作员直出1700µs的近似观测，定时模式的±20ms是写入/调度约束，绝不是物理脱离误差已验证为±20ms。任务前由操作员检查装载和机构；不能把这项人工检查写成传感器健康数据。

## 当前启用范围

Ubuntu22.04工程代码和配置已接入timed，但enabled=false、calibrated=false保持。sensor模式calibrated仍要求local_command_direct；timed模式允许显式operator_direct作为估计依据，实际启用前仍需地面验证动作时长、停止和机构状态。本轮未SSH部署新模式、未重建真实PWM基线、未输出脉冲、未解锁无人机；A机当前发布版本仍使用原禁用配置，下一次机载同步和机构测试需按现场条件执行。

## 验证

quick39/39、10项定时模式回归通过；独立网络空间中以普通用户运行ROS真实guard/servo类及MockPWM，无锁扣反馈发布者，正常完成、途中停止、监督丢失三场景通过，物理事件均0。正常场景首个输出1700µs，持续约1.5秒后动作完成；停止/丢失场景无完成事件。原sensor模式ROS链、操作员动作前/中停止和launch延迟/模式参数求值通过。首次ROS测试仅因两个话题回调先后次序的测试假设失败，修正为等待两者送达后重跑通过；保留原日志。
